# Decisions

Choices made while building where the docs did not answer. One line of reason each.

| #   | Decision                                                                                                                                                                                                                                    | Reason                                                                                                                                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | The platform is added next to the existing static site in this repository, without touching the existing files.                                                                                                                             | The repository already serves a live Cloudflare Worker site; deleting it is not asked for.                                                    |
| 2   | `.assetsignore` is extended to exclude `apps`, `packages`, `docs`, `node_modules` and tooling files.                                                                                                                                        | The Worker serves the repo root as static assets, so new source and dependencies must not be published.                                       |
| 3   | pnpm workspaces for the monorepo, no Turborepo.                                                                                                                                                                                             | Simplest option that gives the layout in 04 section 2.                                                                                        |
| 4   | Fonts are self-hosted through Fontsource packages, not Google Fonts at build time.                                                                                                                                                          | Builds do not need network access and there is no third party request at page load.                                                           |
| 5   | TypeScript is pinned to 5.9.3 although 7.x exists.                                                                                                                                                                                          | Next.js and the Auth.js adapter are tested against 5.x.                                                                                       |
| 6   | Auth.js uses database sessions. `auth_identities` doubles as the Auth.js accounts table, and `sessions` and `verification_tokens` tables are added, plus `email_verified`, `adult_confirmed_at` and `terms_accepted_at` on `users`.         | The adapter needs these shapes, and 03 section 1 asks for the age confirmation time to be stored.                                             |
| 7   | Email sign up creates the user row (with age and terms confirmation) before the link is sent. Google and Discord sign up sets a short lived consent cookie that the sign in callback checks. Sign in refuses accounts that never confirmed. | Consent must be stored for every account, including when the link is opened on another device.                                                |
| 8   | Sign in shows the same message whether or not the email has an account.                                                                                                                                                                     | Stops the form being used to find out who has an account.                                                                                     |
| 9   | Anonymous visitors to `/admin` are redirected to sign in. Signed in people without the role get a 403 page. The API answers 401 when not signed in and 403 without the role.                                                                | A redirect is the useful answer for a staff member who forgot to sign in. Everyone without access is still refused.                           |
| 10  | A catch all route under `/api/v1/admin` checks the staff role before any lookup.                                                                                                                                                            | A non staff caller can never learn which admin routes exist.                                                                                  |
| 11  | Sign in rate limits are held in memory in Phase 0. Redis replaces them when the job queue is added.                                                                                                                                         | Redis is introduced with BullMQ in a later phase and one process is enough for development.                                                   |
| 12  | With no `EMAIL_API_KEY`, sign in emails print to the server console, and to a file when `DEV_EMAIL_OUTBOX` is set.                                                                                                                          | Meets the rule that the app starts with only `DATABASE_URL`, `REDIS_URL` and `AUTH_SECRET`.                                                   |
| 13  | Selects use the native element styled to the input shape.                                                                                                                                                                                   | Native selects keep keyboard and touch behaviour correct, and radix is allowed but not required.                                              |
| 14  | Platform marks are single letter monograms until licensed logos are supplied.                                                                                                                                                               | No logo files were provided and invented logos are not allowed.                                                                               |
| 15  | Private campaigns are left out of public lists.                                                                                                                                                                                             | The docs say private campaigns need an access code, so listing them would leak them.                                                          |
| 16  | Database triggers make `audit_log`, `ledger_transactions` and `ledger_entries` read only, and keep `updated_at` current. The deferred trigger that rejects unbalanced transactions comes in Phase 1 as planned.                             | 02 section 1 says money rows are never edited, and 03 section 13 says audit rows cannot be changed.                                           |
| 17  | Home page navigation points to anchors on the home page. Legal links and campaign detail links lead to pages built in Phase 2.                                                                                                              | Those pages are Phase 2 work and are not faked in Phase 0.                                                                                    |
| 18  | The dev seed marks every fake row with `@seed.invalid` emails, `(seed)` client names and `SEED DATA` notes, and refuses to run when `NODE_ENV` is production.                                                                               | 04 section 6 requires seed data to be clearly marked and never shown in production.                                                           |
| 19  | Staff two factor sign in is not built in Phase 0. The `require_staff_2fa` setting exists.                                                                                                                                                   | Phase 0 acceptance does not include it. It must be built before launch (launch checklist).                                                    |
| 20  | A campaign moves to `closing` when its budget balance reaches 0 after an accrual.                                                                                                                                                           | The smallest possible payment is 1 cent, so "less than the smallest possible payment" means 0 in whole cents.                                 |
| 21  | Earning idempotency keys are `earning:{submission}:{counted views}:{movement number}` (and `earning_reversed:` the same way), not only the counted views.                                                                                   | A post that goes 10,000 to 9,000 and back to 10,000 views would otherwise reuse an old key and the ledger would stop matching the submission. |
| 22  | A creator's pending balance equals the earned cents of their submissions in `approved`, `earning`, `flagged` or `final`.                                                                                                                    | Flagged and final posts still hold earned money in pending, so the doc's "approved or earning" would not balance.                             |
| 23  | `@mde/money` has two entry points: the main one is pure (formatting, earnings, fees), `@mde/money/ledger` talks to the database.                                                                                                            | The UI uses the money formatting in the browser and must not bundle the database driver.                                                      |
| 24  | `ledger_transactions.payout_id` stores the withdrawal id for withdrawal movements.                                                                                                                                                          | The table has no separate withdrawal column and the id is needed to trace a payout.                                                           |
| 25  | Releasing earnings skips suspended creators, and rejecting a `paid_out` post is refused.                                                                                                                                                    | 03 section 8 says releasing for a suspended creator is a finance decision, and 02 section 5.4 says money is never clawed back automatically.  |
| 26  | A withdrawal moves money to `payout_in_transit` when it is requested, with the fee worked out then but taken only when the partner confirms.                                                                                                | This is the order in the transaction table in 02 section 4.                                                                                   |
| 27  | The money package tests use their own database, `mde_test_money`.                                                                                                                                                                           | Packages run their tests in parallel and must not reset each other's data.                                                                    |
| 28  | `recordClientFunding` takes an optional campaign id.                                                                                                                                                                                        | Funding is entered per campaign in Phase 2, and the receipt should be traceable to it.                                                        |
| 29  | Manual adjustments and the return of unused budget at close are not built in Phase 1.                                                                                                                                                       | They belong to the ledger screen (Phase 7) and to payouts (Phase 6) in the plan.                                                              |
